# PG17 + AGE 1.6.0 → PG18 + AGE 1.7.0 major upgrade plan

**Author:** dream-team / Aurora
**Date:** 2026-05-26
**Issue:** [#234](https://github.com/techempower-org/mempalace/issues/234)
**Status:** Plan (monitor-and-wait — do not execute against the canonical
palace before all trigger conditions in §Trigger conditions are met)
**Scope:** `mempalace-db` container on `familiar.jphe.in` (bind-mount
`/var/lib/mempalace-db` → `/var/lib/postgresql/data`, image
`mempalace-db:0.2-pg17` post-PR #231, built from
`disks/mempalace-db/Dockerfile` on the host in the `disks` repo).

---

## TL;DR

- **Target stack:** Postgres 18 + Apache AGE 1.7.0 + pgvector 0.8.2.
- **Status today:** **WAIT.** AGE 1.7.0 ships only as
  `release/PG18/v1.7.0-rc0` (release-candidate, tagged 2026-01-21) and
  the `release_PG18_1.7.0` Docker tag is published but unannotated as
  GA-equivalent in the AGE release notes. We do not move until AGE
  upstream cuts a non-RC `1.7.0` tag for PG18, or until we have made
  a deliberate decision to accept the RC.
- **Predecessor:** [PR #231](https://github.com/techempower-org/mempalace/pull/231)
  lands PG16 → PG17 with AGE pinned at 1.6.0. **This plan composes on
  that bake-in.** Do not run this plan before PG17 has been the
  production cluster for at least 14 days.
- **Compounded risk surface:** PG18 ships four breaking-change vectors
  (data-checksum default on, MD5 password deprecation warning,
  VACUUM/ANALYZE inheritance default change, FTS uses cluster default
  collation provider) in addition to the AGE 1.6 → 1.7 upgrade-script
  cost. The PG17 plan deliberately split these. This plan owns both.
- **Approach:** identical mechanically to PR #231 — parallel container
  on port 5434, dump-and-restore, side-by-side smoke tests, then a
  container-rename cutover. The difference is in the smoke-test matrix
  (now exercises AGE 1.7's RLS + `age_load` changes) and the
  pre-flight (now includes a PG18 checksum decision and an MD5 → SCRAM
  password rotation).

The trade-off in one paragraph: PG17 bought us the immediate
performance wins (VACUUM overhaul, B-tree `IN`-list scans, parallel
BRIN). PG18 buys us the I/O subsystem rewrite (the upstream press kit
claims up to 3× read throughput from storage) and B-tree skip scans,
both of which become relevant when (a) the OS page cache is cold on
familiar after the next reboot or (b) drawer-count growth pushes
us past the in-memory working set. We are not in either regime today;
the upgrade is forward-looking, not reactive.

## Trigger conditions

This plan converts from "monitor" to "execute" only when **all** of
the following are true. The operator must confirm each item on the
day of the window.

1. **AGE 1.7.0 is released as a non-RC tag for PG18.** The release
   that exists today is `release/PG18/v1.7.0-rc0` (2026-01-21). A
   non-RC tag would appear at `apache/age` releases as
   `release/PG18/v1.7.0` (no `-rc` suffix). Track via
   [apache/age/releases](https://github.com/apache/age/releases) and
   [issue #2229](https://github.com/apache/age/issues/2229).
   - **Override clause:** if the RC has been published for ≥6 months
     with no GA-equivalent tag, we may choose to adopt the RC after a
     focused rehearsal on a side-by-side container. This is a
     deliberate decision JP must sign off on, not a default.
2. **PG17 has been in production for ≥14 days** with no unresolved
   regressions. Measure from the PR #231 cutover commit.
3. **pgvector PGDG apt build for PG18 is still on the same 0.8.x
   point version we currently run** (today: `0.8.2-1.pgdg13+1`). If
   pgvector has moved to 0.9.x in the meantime, treat that as a
   separate upgrade decision (its own plan, its own bake-in).
4. **AGE Docker image `apache/age:release_PG18_1.7.0` is published**
   (verify on [Docker Hub](https://hub.docker.com/r/apache/age/tags)).
   The tag exists today but trigger condition #1 gates whether we
   trust it as GA-equivalent.
5. **A rehearsal of `age--1.6.0--1.7.0.sql` against a
   pg_dump-restored side-by-side container has completed.** The AGE
   release notes warn the upgrade script "may take a while to
   complete for large graphs, due to creation of indexes for existing
   labels." With 516K vertices and 535K edges (count as of 2026-05-26
   per PR #231 Phase A) we must time this before the cutover window.
6. **MD5 → SCRAM password rotation for the `palace` role is staged.**
   PG18 emits warnings (not errors) on MD5 passwords. The rotation
   itself is trivial (`ALTER USER palace PASSWORD '...';` after
   `password_encryption = scram-sha-256`) but it belongs in this
   window so the warnings stop on day one.

If any condition is unmet on the planned window day, **postpone**.
Do not skip a condition to hit a calendar slot.

### Breaking changes inherited from PG18

| Change | What changes | Our exposure | Mitigation |
|---|---|---|---|
| `initdb` defaults `--data-checksums` on | New clusters get checksums by default; existing clusters keep their setting through `pg_upgrade`, but `pg_dump`/`pg_restore` (our approach) crosses the boundary cleanly because checksums are a cluster-init property, not a dump-content property. | Low — we restore into a fresh cluster, so the new cluster takes whatever `initdb` flags we pass. **Decision required:** enable checksums now or stay consistent with current PG17 cluster. | Pre-flight §6 |
| MD5 password deprecation | `CREATE ROLE` / `ALTER ROLE` with MD5 emits a deprecation warning. Authentication still works. | Medium — the `palace` role is MD5 today (inherited from PG16 era). Every daemon startup will emit a warning into `journalctl`. | Rotate to SCRAM during this window (pre-flight §7) |
| VACUUM/ANALYZE inheritance default | `VACUUM ANALYZE` on a partitioned parent now propagates to children by default in 18; previously required explicit `ANALYZE` of partitions. | Low — we don't use partitioning today. `mempalace_drawers`, `mempalace_kg_extraction_queue` are single tables. | None required; document in §Open questions for future use |
| FTS cluster default collation provider | Full-text search functions now use the cluster's default collation provider for some operations; previously used C locale. | Low — we don't expose FTS to user search; pgvector + AGE handle ranking. | Smoke #2 verifies no collation-mismatch on restore |
| `pg_stat_wal` columns removed | The `wal_buffers_full` column moves; old monitoring queries break. | None — we don't monitor `pg_stat_wal` from app code. | None required |

### Breaking changes inherited from AGE 1.7

| Change | What changes | Our exposure | Mitigation |
|---|---|---|---|
| Upgrade script index rebuild | `age--1.6.0--1.7.0.sql` builds indexes for every existing vertex/edge label. Timing scales with `(labels × rows)`. | High — 516K vertices + 535K edges across the labels we use. Time this in pre-flight §5 rehearsal. | Rehearsal gates the window length |
| Replaced libcsv with pg COPY for `age_load` | CSV-loading semantics for graph bulk import change; quoted-field handling differs in edge cases. | None — we don't use `age_load`; the daemon writes to AGE via cypher() exclusively. | None required; document for future bulk-load work |
| `age_load` restrictions tightened | Permission model around the function changed. | None — same as above. | None required |
| RLS support added + permission-check fix (#2309) | Read-side cypher() now respects row-level security policies on backing label tables. | None today — we don't define RLS policies. **Implication:** future RLS work on `mempalace_kg` becomes possible without a fork. | Document as a forward-looking capability |
| Ambiguous column reference fix (#1884) | Some cypher() patterns that returned a column name twice now error or rename. | Low — our cypher() shapes are simple `MATCH (e:Entity {name: ...}) RETURN e`. Smoke #4 verifies the hot read shape. | Smoke matrix #4, #5, #10 |
| Empty list in `IN` handling | `WHERE x IN []` now evaluates to `false` instead of erroring. | None — the daemon does not generate empty-list `IN` clauses; pre-extraction filters guard against this. | None required |
| ORDER BY alias resolution fix | `RETURN x AS y ORDER BY y` now resolves correctly. | None — we don't use `ORDER BY` in cypher() reads. | None required |

```bash
    -U palace -d mempalace_2026_05_13 --no-owner --no-privileges \
    -j 4 /tmp/dump.bin'

# AGE 1.7 ships in a separate Docker image; install the 1.7 .so into
# the rehearsal container manually for the upgrade-script test, OR
# run pg_dump-out + pg_restore-into-pg18 (the actual path we'll use).

# Stand up PG18 + AGE 1.7 alongside

    --name mempalace-db-pg18-rehearsal \
```

### 6. Data checksums decision

**New in this plan.** PG18's `initdb` defaults to data checksums on.
PR #231 left PG17 with checksums off (to match PG16). Three options:

| Option | What | Cost | Recommendation |
|---|---|---|---|
| A | New PG18 cluster starts with checksums **off** (`initdb --no-data-checksums`) | Zero — `pg_dump`/`pg_restore` doesn't carry checksums | **Default** — matches PG17 state, no new behavior |
| B | New PG18 cluster starts with checksums **on** (default) | Small write overhead (~2-5% on heavy-write workloads) | Pick if we want detection of latent disk corruption |
| C | Start with checksums off, enable later via `pg_checksums --enable` (offline) | One ~3-5 min offline pass on the 3.6 GB DB during a future window | Reasonable middle ground; defer the decision |

**Default recommendation: Option A** (matches PR #231 state). Revisit
in a future operator doc if disk-corruption-detection becomes a
priority. Document the choice in the cutover commit.

### 7. MD5 → SCRAM password rotation staging

**New in this plan.** Stage the rotation so the cutover window
applies it cleanly.

```bash
# On the PG17 cluster, change the encryption setting (does NOT re-hash
# existing passwords — that happens on the next ALTER USER ... PASSWORD)
ssh familiar 'docker exec mempalace-db psql -U palace -d mempalace_2026_05_13 \
    -c "ALTER SYSTEM SET password_encryption = '\''scram-sha-256'\'';"'

# After cutover (in Phase E), the operator runs:
#   ALTER USER palace PASSWORD '<same password>';
# which re-hashes with SCRAM. Same password value, new hash format.
# pg_hba.conf in the AGE base image already accepts both md5 and
# scram-sha-256 by default ('host all all all md5' should be replaced
# with 'host all all all scram-sha-256' as part of the Dockerfile bump).
```

**Verify the change is staged but not active:**

```bash
ssh familiar 'docker exec mempalace-db psql -U palace -d mempalace_2026_05_13 \
    -c "SHOW password_encryption;"'
# Expected: scram-sha-256 (or md5 if ALTER SYSTEM hasn't been reloaded yet)
```

## Step-by-step command sequence

The phases match PR #231's shape. Only the image tag, base image
version, and post-restore SCRAM rotation differ.

### Phase A — build the new image

On katana (where the Dockerfile lives at
`~/Projects/disks/mempalace-db/Dockerfile`):

```bash
cd ~/Projects/disks/mempalace-db
git switch -c chore/pg18-age1.7-upgrade

# Bump base image and pgvector apt package
sed -i 's|apache/age:release_PG17_1.6.0|apache/age:release_PG18_1.7.0|' Dockerfile
sed -i 's|postgresql-17-pgvector|postgresql-18-pgvector|' Dockerfile

# pg_hba.conf for SCRAM (if not already done by base image)
# Add: RUN sed -i 's/md5$/scram-sha-256/' /etc/postgresql/18/main/pg_hba.conf
# OR ensure the upstream apache/age:release_PG18_1.7.0 image ships scram by default.

docker build -t mempalace-db:0.3-pg18 .

# Verify
docker run --rm mempalace-db:0.3-pg18 \
    bash -c "psql --version && dpkg -l | grep -E 'postgresql-18|pgvector'"
```

Push the Dockerfile change to `disks/mempalace-db/` so the build is
reproducible. Side-load onto familiar:

```bash
docker save mempalace-db:0.3-pg18 | ssh familiar 'sudo docker load'
ssh familiar 'docker images mempalace-db'
```

### Phase B — stand up the new container on port 5434

```bash
ssh familiar 'sudo mkdir -p /var/lib/mempalace-db-pg18 && \
    sudo chown 999:999 /var/lib/mempalace-db-pg18'

# initdb flags: pick --no-data-checksums per pre-flight §6 default
ssh familiar 'docker run -d \
    --name mempalace-db-pg18 \
    --restart unless-stopped \
    -p 5434:5432 \
    -e POSTGRES_USER=palace \
    -e POSTGRES_PASSWORD="$(bw get password mempalace-db-postgres)" \
    -e POSTGRES_DB=mempalace_test \
    -e POSTGRES_INITDB_ARGS="--no-data-checksums --encoding=UTF8 --locale=en_US.UTF-8" \
    -v /var/lib/mempalace-db-pg18:/var/lib/postgresql/data \
    -v /opt/mempalace-db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro \
    mempalace-db:0.3-pg18'

ssh familiar 'until docker exec mempalace-db-pg18 pg_isready -U palace; do sleep 1; done'
```

### Phase C — restore the dump into the new container

```bash
ssh familiar 'docker cp /home/jp/backups/mempalace_pre_pg18_$(date +%Y%m%d).dump \
    mempalace-db-pg18:/tmp/dump.bin'

ssh familiar 'docker exec mempalace-db-pg18 psql -U palace -d mempalace_test \
    -c "CREATE DATABASE mempalace_2026_05_13 OWNER palace;"'

# Create extensions BEFORE pg_restore — AGE catalog restore depends on it
ssh familiar 'docker exec mempalace-db-pg18 psql -U palace -d mempalace_2026_05_13 \
    -c "CREATE EXTENSION IF NOT EXISTS age; LOAD '\''age'\'';
        CREATE EXTENSION IF NOT EXISTS vector;"'

ssh familiar 'docker exec mempalace-db-pg18 pg_restore \
    -U palace -d mempalace_2026_05_13 \
    --no-owner --no-privileges \
    -j 4 \
    /tmp/dump.bin 2>&1 | tee /tmp/restore.log'
```

Expected timing: **rehearsal-validated** in pre-flight §5. If the
real restore exceeds that timing by >50%, abort and investigate
before cutover.

### Phase D — SCRAM password rotation

**New phase relative to PR #231.** Run after restore, before smoke tests.

```bash
ssh familiar 'docker exec mempalace-db-pg18 psql -U palace -d mempalace_2026_05_13 \
    -c "SHOW password_encryption;"'
# Expected: scram-sha-256 (PG18 default)

# Re-hash the palace password (same value, new hash format)
ssh familiar 'docker exec mempalace-db-pg18 psql -U palace -d mempalace_2026_05_13 \
    -c "ALTER USER palace PASSWORD '\''$(bw get password mempalace-db-postgres)'\'';"'

# Verify the hash format changed
ssh familiar 'docker exec mempalace-db-pg18 psql -U palace -d mempalace_2026_05_13 \
    -c "SELECT rolname, substring(rolpassword for 6) FROM pg_authid WHERE rolname = '\''palace'\'';"'
# Expected: rolpassword starts with 'SCRAM-' not 'md5'
```

### Phase E — run the smoke-test matrix (pre-cutover)

See §Smoke-test matrix below. Block on a clean pass for **every**
test. AGE-specific tests #4-5, #10, #14, plus the new tests #16-19
that exercise AGE 1.7 behavior changes, must all pass.

### Phase F — cut over

```bash
# 1. Halt daemon (graceful flush completes within 5 s)
ssh familiar 'sudo systemctl stop palace-daemon'

# 2. Stop old PG17 container (do NOT remove yet)
ssh familiar 'sudo docker stop mempalace-db'

# 3. Container rename swap (zero DSN edit)
ssh familiar 'sudo docker stop mempalace-db-pg18 && \
    sudo docker rename mempalace-db mempalace-db-pg17-retired && \
    sudo docker rename mempalace-db-pg18 mempalace-db && \
    sudo docker run -d \
        --name mempalace-db \
        --restart unless-stopped \
        -p 5432:5432 \
        -v /var/lib/mempalace-db-pg18:/var/lib/postgresql/data \
        mempalace-db:0.3-pg18'

# (Alternative: edit /etc/palace-daemon/env to change PG_PORT to 5434.
# Container-rename is preferred because it makes the cutover visible

# 4. Start daemon
ssh familiar 'sudo systemctl start palace-daemon'

# 5. Verify
sleep 5
curl -sf -H "X-API-Key: $PALACE_API_KEY" http://familiar:8085/health
curl -sf -H "X-API-Key: $PALACE_API_KEY" http://familiar:8085/status/fast | jq '.total_drawers'
```

Expected: `total_drawers` equals the pre-cutover value (zero drift
because the extraction queue is halted).


## Rollback procedure

Time-bounded, same shape as PR #231 but with the rollback target being
PG17 + AGE 1.6.0 (the post-#231 production state), not PG16 + AGE 1.6.

### Within Phase F (haven't started daemon on PG18 yet)

Trivial — both containers still on disk:

```bash
ssh familiar 'sudo docker stop mempalace-db && \
    sudo docker rename mempalace-db mempalace-db-pg18-failed && \
    sudo docker rename mempalace-db-pg17-retired mempalace-db && \
    sudo docker start mempalace-db && \
    sudo systemctl start palace-daemon'
```

Verify: `curl http://familiar:8085/status/fast` returns the pre-window
drawer count.

### Within 4 hours post-cutover (PG18 has accepted writes)

Same two-option pattern as PR #231:

**Option 1 — replay deltas onto PG17.** Diff writes since the dump
out of PG18 and apply to PG17. AGE deltas are non-trivial to replay
(cypher() writes aren't easily expressed as `COPY`); if the only
writes since cutover are to `mempalace_drawers` and
`mempalace_kg_extraction_queue` (no AGE cypher() writes — i.e., the
extraction queue was held in Phase G), this is easy. If the
extraction queue has been running, prefer Option 2.

**Option 2 — accept the window's writes as lost.** Restore from the
filesystem snapshot taken in Pre-flight §3:

```bash
ssh familiar 'sudo systemctl stop palace-daemon
              sudo docker stop mempalace-db
              sudo rm -rf /var/lib/mempalace-db.broken && \
              sudo mv /var/lib/mempalace-db /var/lib/mempalace-db.broken && \
              sudo cp -al /var/lib/mempalace-db.pre-pg18-* /var/lib/mempalace-db
              sudo docker rename mempalace-db mempalace-db-pg18-failed
              sudo docker rename mempalace-db-pg17-retired mempalace-db
              sudo docker start mempalace-db
              sudo systemctl start palace-daemon'
```

### Beyond 4 hours

Forward-fix. Do not roll back. The cost of replaying or discarding
hours of cypher() writes to `mempalace_kg` exceeds the cost of
patching the regression in place.

## Risk register

Inherits PR #231's risk register; adds the AGE-1.7-specific and
PG18-specific risks.

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **AGE 1.7 RC instability** (we're adopting a release candidate) | Medium | High | Trigger condition #1 gates on a non-RC tag. Override clause exists but requires JP sign-off + rehearsal evidence. |
| **AGE 1.6 → 1.7 upgrade script slow** on large graphs | Medium | Medium | Pre-flight §5 rehearsal times this before the window commits |
| **pg_dump / pg_restore corruption** of AGE catalog tables (PG17 → PG18 + AGE 1.6 → 1.7 crossing) | Medium | High | Smoke #4, #10, #16, #17 catch regressions before cutover. Pre-flight §5 rehearsal also exercises this path. |
| **pgvector index rebuild** during restore (HNSW segments not bit-for-bit portable across PG majors) | Medium | High | HNSW indexes rebuild from rows during restore. Smoke #8 verifies ANN latency post-rebuild. `REINDEX CONCURRENTLY` available as fallback. |
| **Daemon DSN mismatch** post-cutover | Medium | Medium | Container-rename approach (Phase F §3) avoids DSN edit entirely. Smoke #11 catches a DSN miss in <30 s. |
| **SCRAM rotation failure** (re-hashing breaks auth mid-cutover) | Low | Critical | Phase D runs the rotation BEFORE daemon startup. Smoke #18 verifies SCRAM auth works before daemon connects. Rollback: re-hash to MD5 (`SET password_encryption = 'md5'; ALTER USER palace PASSWORD '...';`) and accept the deprecation warnings. |
| **PG18 plan regression** on a hot search query (planner changes pick worse plan) | Medium | Medium | Re-run `EXPLAIN ANALYZE` for top 10 search shapes on PG18 before cutover. AIO subsystem is new; pg_stat_io reads can guide tuning. |
| **AIO subsystem regression** (PG18 new I/O paths may surface kernel/storage quirks) | Low | Medium | familiar's disk subsystem is unchanged (local NVMe, ext4). AIO defaults are conservative. If issues appear, set `io_method = sync` to disable. |
| **VACUUM/ANALYZE inheritance change** breaks an extraction worker query | Low | Low | We don't use partitioning today. Document for future use. |
| **FTS collation provider change** affects pgvector or AGE indexes | Low | Low | We don't use FTS. Smoke #2 verifies extensions load cleanly. |
| **Disk exhaustion** mid-restore | Low | Critical | Pre-flight §1 gates on 3× DB size free. |
| **Backfill workers reconnect to wrong cluster** | Low | Medium | Workers read DSN via daemon endpoints, not direct PG. Phase G restarts them cleanly after daemon is healthy. |
| **Daemon graceful shutdown** doesn't drain in-flight writes | Low | Medium | Same as PR #231: pre-flight §4 halts the largest writer; daemon flushes within 5 s. |
| **AGE 1.7 cypher() syntax regression** on hot read shapes | Low | High | Smoke #4 verifies the dominant read shape. Smoke #16 verifies the ambiguous-column fix. If regression appears, pin AGE at 1.6.0 by reverting Dockerfile tag and rolling back. |

## Open questions

Items deliberately unresolved at the time of plan authorship. Each is
either gated on upstream signal we don't have yet, or a deliberate
deferral until the operator window.

1. **AGE 1.7.0 non-RC release date.** TBD: needs upstream signal.
   Today: `release/PG18/v1.7.0-rc0` is the only PG18 tag. Track
   [apache/age/releases](https://github.com/apache/age/releases) and
   [apache/age#2229](https://github.com/apache/age/issues/2229).
2. **AGE Docker tag `apache/age:release_PG18_1.7.0` GA-equivalence.**
   The tag exists on Docker Hub (per PR #231 verification) but is
   built from the `release/PG18/v1.7.0-rc0` branch. Confirm at
   window time whether `apache/age` has cut a GA-tagged image.
3. **PG18 upgrade-script timing on our graph.** TBD: pre-flight §5
   rehearsal. Without an actual measurement we cannot commit to a
   window length.
4. **Whether to enable data checksums.** Pre-flight §6 defaults to
   Option A (off, matches PG17). The decision belongs to the
   operator at window time, with a recorded rationale in the cutover
   commit.
5. **AIO tuning baseline.** PG18's `io_method` defaults to `worker`.
   `io_workers` defaults to 3. We have no prior data on what these
   values should be for our workload. TBD: post-cutover bake-in
   should include a `pg_stat_io` read at T+24h to establish a
   baseline.
6. **pgvector 0.9.x availability.** Today: 0.8.2 is the latest tag.
   If 0.9.x ships before this window, treat as separate upgrade
   (its own plan, its own bake-in). Do not bundle.
7. **Whether to swap to a multi-stage Dockerfile** that pins
   pgvector to a specific commit. PR #231 §5 marked this as
   deferred; same call here unless we hit a pgvector apt
   availability issue.
8. **AGE 1.7 RLS adoption plan.** AGE 1.7 added RLS support on
   cypher() reads. We don't define RLS policies today. Question for
   a future plan: does single-tenant memorypalace ever need RLS
   (e.g., to wall off agent-diary wings from cross-agent reads)?
   Forward-looking only — not in scope here.
9. **PG18 `uuidv7()` adoption.** PG18 ships native `uuidv7()`. The
   daemon currently generates UUIDs in application code. Migrating
   to `uuidv7()` would give us timestamp-ordered drawer IDs (better
   B-tree locality on inserts). Forward-looking only — separate
   issue if we decide to pursue.
